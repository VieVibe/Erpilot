# 部署与身份补强结构化自审

日期：2026-11-04；按已读取的 code-review-expert 安全、设计和质量清单单人复核，
不是独立第三方审计。范围为本轮账号/权限、ASGI/SSE、镜像、前端身份、流资源释放、CI 和交付。

| 发现或设计风险 | 处置 | 验证 |
|---|---|---|
| session_id/pending_id 不能作为账号凭证；旧审批接口仅给 pending_id 容易绕过资源归属 | 服务端签发新会话、owner SQL 过滤、run 经会话授权；旧审批增加 session_id 与当前 checkpoint pending 对照 | 跨用户 GET/POST、自己的 sid + 别人的 pending、匿名旧会话不可认领 |
| 只禁用前端按钮不能限制模型或直接 HTTP 写入 | operator 风险工具从服务端注册表移除，确认/审批/恢复入口独立校验角色 | 模型请求写工具无业务改变；直接确认/审批 403；正常 approver 提交一次 |
| 同源 cookie 需要 CSRF 与来源约束，异常参数不能触发 500 | HttpOnly/Strict、同步 token、来源、JSON/2MiB 限制；非 ASCII token 按 bytes 比较，空登录 JSON 返回 422 | cookie/CSRF/Origin、坏 JSON/空体/超大体、Secure 配置等负例 |
| 同一浏览器账号切换可能遗留 sid 或被旧请求的延迟 401 登出 | sid 以 user_id 命名，token 只在内存；401 对照发出时的身份 token | 两个账号真实容器切换和客户端延迟 401 回归 |
| 取消模型流后未立即关闭内部生成器，HTTP 流等 GC 才释放 | 外部消费者关闭时显式 `aclosing` 内部流 | SDK/HTTP 替身回归修复前失败、修复后 31 个 LLM 用例及全仓通过 |
| 首次初始化中断可能留下半份 ERP 数据；重建不应覆盖已有业务 | 临时文件完整初始化后原子发布，已有目标不覆盖，临时文件清理 | 中断/重试、并发目标已出现、已有数据保留 |
| 容器沿用“临时数据、重启清空”提示，登录必填星号污染可访问名称 | 显式 persistent demo 能力与文案；输入框声明正确名称 | 容器浏览器检查持久提示、登录及两个视口截图 |
| 金额同时存在于隐藏草稿与审批卡，审批标签含计数 | 浏览器定位限定到审批 tabpanel 并允许动态计数 | 正式离线 API 5 个浏览器用例通过 |
| 新容器文件可能被交付白名单遗漏，运行凭证可能进入构建/源码 | 增加 Dockerfile/.dockerignore/live override；镜像上下文和源码双重排除环境/数据 | 打包用例、实际构建/探针、最终清单和已配置密钥精确匹配检查 |

补充检查：密码派生在线程池执行；登录尝试以事务预留防并发绕过；token 摘要持久化、到期/撤销；
SSE 响应不缓冲；审计不把 200 当事务成功、不记录密码/令牌/原话；SQL 参数化且 owner 在数据库分页。
默认镜像不加载模型密钥；真实配置只启动和查探针，未追加付费生成。

最终工程范围内无已知未处理 P0/P1 问题。完整真实任务质量仍未达标，不能视作发布质量门槛已通过。
`async generator already executing` 与真实连接失败的关系没有证明，不以离线修复改判真实结果。
未进行完整依赖漏洞数据库审计、公网渗透或多 worker 测试。
