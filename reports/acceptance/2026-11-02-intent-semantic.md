# 意图分析 P2：创建候选、完整表单与统一预算

日期：2026-11-02。接续[整轮诊断](2026-11-02-intent-diagnostics.md)，仅覆盖创建草稿的语义候选。
默认 `off` 且 `intent_semantic_settings=None`，没有修改 `.env`、正式数据库、人工标签、旧 scorer 或历史结果。
所有模型及 SDK HTTP 测试均为脚本/MockTransport，没有供应商请求或付费调用。

## 行为

已支持的规则表达保持原路径。只有显式配置 API 的语义设置、独立预算标识及已确认费率后，
规则无法覆盖的新创建表达才允许一次候选请求；条件、否定、引文和已识别旧草稿修改屏障不由模型解除。
模型只看当前原始消息及有限 schema，没有业务工具或执行许可。

严格 schema 与实际 Unicode 区间核对阻止未知动作/属性、伪造消息/位置、重叠证据、
布尔件数、非有限数字、重复 JSON 键、包装换算与引文数据变成创建候选。
商品只绑定真实精确名称/SKU，目录重名不默认选第一项；价格、状态、名称、类别及候选集合参与指纹。
本档一律进入完整可编辑表单，不产生自动保存许可。

页面显示完整原话和尚未映射的原文，明确字段只是待核对候选。
只有用户点击完整清单确认才创建草稿，历史使用 `manual_form`，保留原始消息、原始候选和明确表单核对标记。
保存仍在事务中重查来源、目录、会话、版本和有效期；简短回复不确认表单，重复确认不能多建。
异步候选返回时已有新待完成请求会拒绝旧结果，不覆盖新请求。

## 计量

原 `evals.billing` 实现迁至业务无关的 `agent_core.billing`，旧导入兼容；原费率条目、
计价公式、原币种与缓存未知时的上界估算口径保持。增加流关闭，确保取消也结算为未知。
语义和业务请求共享同一当前客户端、费率、金额/次数预算；实际模型及端点主机须与费率一致。
请求日志记录用途、真实轮次/来源哈希、usage、原币种估价、未知状态，诊断按用途分别计数并汇总。
原业务循环 `LoopEnd` 的 usage 不包括额外分析，统一账本才是两类请求的合计。

轮次请求前先持久化占用；同轮重复解析、失败或宿主重建都不会重发意图请求。
HTTP 自动重试关闭，不用修复 JSON 的第二次请求。无余额不初始化模型，
缺 usage、超时、非法用量、中断及未结算请求在重建后仍保留未知，不清零或混算币种。
固定预算配置不能被同名新配置覆盖，配置过语义的工具源不能泄漏给另一个不计量宿主。
这批 API 接线显式配置生效，普通启动和 CLI 不自动开启新请求。
