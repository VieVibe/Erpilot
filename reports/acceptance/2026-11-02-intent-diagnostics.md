# 意图分析：整轮诊断与带状态压力验证

日期：2026-11-02。接续[创建预览](2026-10-31-intent-preview.md)，对应设计 P0/P1 的本地可验证剩余项。
默认仍为 `off`；没有修改 `.env`、用户数据库、原核心标签、旧 scorer 或历史验收结果，没有供应商请求。

## 变更

API 的 `shadow/enforce` 执行段新增本地 `.intent.jsonl`，和原 trace 同前缀。
每轮包含版本、输入引用和真实当前原话，记录规则/影子分析、未决项、核验拒绝、阶段许可，
将工具尝试、实际执行、结果与实际保存版本分开。闲聊无工具也留证，GET 恢复不写；`off` 不建新文件。
诊断不是业务来源或执行条件，磁盘故障仅停止该段留证并记录警告。

逐步模型开始和 usage 来自运行时事件；缺失及中断保留未知，不推算成零费用。
运行时开始数不是供应商实际计费请求数，原 trace 和预算协议仍是计费来源。
恢复执行的新段独立编号并关联运行 ID，已写前缀可读取；缺结束事件不冒充完成。
目前自动接入 API 宿主，直接存储/MCP/CLI 调用不自动建立整轮文件；新增恢复段测试属于脚本注入，未声称完成旧 checkpoint 模式切换演练。

新增独立 `evals.intent_state_benchmark` 四流程，不改旧单轮基准或标签。
压力验证发现补件数时回复“三箱”会被当作换题并覆盖上下文，现改为只分类成补充尝试，
继续严格拒绝包装换算，保留原字段、版本和有效期。同轮附带的预算变更也不会先应用。
规则版本升为 `order-rules-5`；旧保存来源仍按原契约读取和复核。

## 四项压力范围

| 流程 | 固定检查 |
|---|---|
| 100 项重名且缺件数 | 每项选择第二个并补三件，10 次宿主重建、重复解析及无效编号，完整清单一次保存 |
| 100 项件数、31,999 字符来源 | 100 次三件补充，包装回复保持状态，原始来源原样保留 |
| 16 会话 | 跨会话没有上下文，目录变化及过期不能继续绑定，没有草稿或订单 |
| 8 并发确认 | 同一应用来源只有一份草稿，七个过期版本拒绝，库存不变 |

两个长流程均保存全部 102 条接受消息，拒绝第 103 条增量且不延长 TTL；
保存前业务表不变，保存后库存不变、订单为零。
31,999 字符来源以合法尾部空白补足，验证长度及原话保留，不把它当成同长度自由表达覆盖。
延迟是本地规则/SQLite/来源重放的逐轮观测，不含模型、HTTP/MCP、网页及诊断 I/O；
没有冻结延迟门槛或与旧算法编造提升比例。
单独运行时，100 项重名补充的逐轮 p50/p95 为 25.9598/31.7880 ms，
31,999 字符来源为 47.4643/51.6355 ms；每项各 108 个混合轮次样本，包含初始、无效及重放调用，
不是重复运行的稳定性能估计。8 个并发确认得到一份草稿和七个 `pending_intent_changed`。
