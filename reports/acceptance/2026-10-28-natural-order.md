# 自然商品输入：名称、中文件数与澄清

2026-10-28。按用户“做第三项”的指令实现。[用户契约与体验入口](../../docs/natural-order-entry.md)。

## 交付

- 完整商品名称 / 明确 SKU 与规范中文件数核对为完整有序清单；支持数量在名称前或后。
- 新只读工具无参数，应用绑定本轮用户原话，在询问模型前核对商品；重名、简称、缺失、
  下架、重复及不明确件数先澄清，不保存部分清单，不按价格或库存替用户选商品。
- 创建参数必须匹配实际解析结果，错误模型参数不产生版本；查询与创建并行不能借用尚未
  返回的结果，旧轮解析不能授权新消息。客户、明确备注与数字预算一并核对。
- 名称 / 中文件数证据在保存事务内重新解析并核对目录，原话与映射随版本保存。
- 已有草稿可按当前唯一商品名或行号修改中文件数，同名商品需明确 SKU / 行号。
- 网页展示原始要求到商品 / SKU / 件数的映射；离线演示新增“商品名称下单”入口。

## 边界

本批只做离线工程与本地浏览器验证，**零付费模型 / 嵌入请求**，没有新增真实模型成功率或
供应商费用。旧政策 v4 的 GLM 13/13、订单真实批次失败与未知费用保持原范围，不推广为
新输入功能的真实验收，也不重开冻结批次。

名称采用精确唯一匹配，模糊结果只是候选；中文件数 1–9999，仅支持“件”。预算仍沿用
明确数字表达。澄清后需要重述本轮完整要求，包括要保留的备注和预算；未实现短回复选单、
别名字典、拼音纠错、包装换算或任意自然语言。原始独立 MCP 没有可信对话来源时不能调用
会话解析工具；可信 Python / 手工表单仍保留既有边界。

模型负责表述与工具选择，业务层核对来源、名称、数量和执行条件。保存草稿不占库存，
实际建单继续要求固定版本人工审批与事务复核。
