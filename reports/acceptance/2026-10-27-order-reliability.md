## 用户可见成果

- 首次对话创建草稿核对完整有序 SKU / 正整数件数；漏项、额外商品、替换、错量、顺序错误在保存前拒绝。
- 不支持的清单、条件、冲突、引用和旧消息不授权创建；可以明确补充清单或在表单逐项核对。
- 创建核验证据在同一保存事务内复核，与原话及草稿版本一起保存。商品来源用独立 `item_constraint`，不破坏旧客户 / 备注来源结构；旧记录不补造初始认证。
- 后端读取时计算预算、有效期、版本、商品现价 / 名称 / 状态及库存事项，保持报价快照不变；页面展示全部原因、处理方式、对应版本及检查时间。
- 多草稿先明确选择；模型不能仅自行读出某个 ID 后修改。网页受阻时禁用提交，核对窗口收到同版本的新阻塞观察也禁用确认。
- 专用确认、模型申请审批前及实际建单事务复核；审批后条件变化仍停止。幂等、原预算与旧批准失效规则继续沿用。
- 新增独立四流程、34 阶段任务集，旧 B4 / 订单 / 预算用例与评分器保持原判。

## 边界

这是有限明确格式的应用执行契约；不是通用自然语言理解、身份认证、商品替代或交期承诺。
原始独立 MCP / 可信 Python 没有真实对话来源，仍可生成未核验来源的草稿；手工表单明确提供完整商品。
没有初始商品核验的旧记录不会因一次修改而被标为整体已核验。
当前检查只是读取时事实，不能替代实际提交事务；页面没有后台锁价或预留库存。
恢复使用共享内存检查点重建宿主，不等同进程重启；本批不部署、不改真实业务库，不重开已跳过的 DeepSeek 验收。
