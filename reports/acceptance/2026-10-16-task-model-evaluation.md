# B4 多轮草稿评测入口验收

日期：2026-10-16。完成七个场景、共十五轮的独立 `--suite b4`，先以 HTTP mock
验证评测装配，再执行用户授权的 GLM / DeepSeek 真实调用。原 baseline 仍为 35 条，
B5 判分未改；模拟测试与真实结果分别记录。

## 场景与证据

| case | 轮数 | 检查重点 |
|---|---:|---|
| b4-second-item | 2 | 模型新建草稿后，将第二行改为 50，客户、备注及第一行保留 |
| b4-repeated-reference | 3 | 第二行改为 50 后再修改第一行，保留上轮结果 |
| b4-ambiguous-draft | 2 | 预置两份当前会话草稿，模糊指代须澄清，零新增版本 |
| b4-selected-draft | 2 | 用户指定客户后，只修改对应草稿 |
| b4-restored-task | 2 | 第二轮清空聊天历史，从数据库任务恢复客户、商品、备注与版本 |
| b4-stale-history | 2 | 两轮间受控交换当前版本商品顺序，按新版本的第二行修改 |
| b4-missing-task | 2 | 当前会话无草稿、其他会话有草稿时，不跨会话读取或修改 |

API 与评测共用 `mcp_erp.draft_tools.DRAFT_GUIDANCE`；工具面与网页会话一致，保留
`submit_order_draft`、取消、库存调整和上下架能力，AutoDeny 兜底。原始 `create_order`
由会话工具面替换为草稿提交流程。禁止的工具尝试即使被审批拒绝，也判失败。

每轮独立检查可见文本与工具成功证据；上一轮的说明不能满足本轮措辞要求。
全表快照要求订单、库存、商品、幂等记录及业务预览保持原样。允许修改草稿的轮次
仅可为明确目标新增一版，原版和其他会话草稿保持原值，客户、备注、SKU 顺序及数量须准确。

JSON 保留 `turn_results`、`turn_traces` 及每轮 `state_evidence`（全表前后哈希、草稿原始行、
历史清空与受控外部版本变化标识）；Markdown 增加逐轮明细。预算熔断或失败后停止后续
轮次，不重放已保存草稿。报告记录实际执行轮数，部分执行不能通过 strict 完整对照；
兼容检查要求相同 `b4_scorer_version`。

恢复场景验证的是聊天历史丢失后的持久任务读取，不代替 PostgreSQL 进程崩溃验收。
预置草稿、外部版本编辑和 HTTP 模型响应均为受控测试条件。

- B4 场景、错误目标/数量/备注/版本、跨会话变更、写入尝试、逐轮文本隔离、

- 21 项跳过包含未配置的 PostgreSQL 集成测试；47 项真实评测由默认 `not eval` 排除。

  Git 忽略的 `.env`，默认 `glm-5.3-flash`，可切换 `deepseek-v4.1-flash`。

- 自动审批最初拒绝联网鉴权检查，原因为尚无将 key 发送给第三方端点的明确授权；
  用户随后明确授权连接验证和 B4 真实评测，原阻碍已解除。`GET /v1/models` 返回 200，
  可用模型恰好包含 GLM 与 DeepSeek。密钥未写入任何可提交文件或报告。

临时目录后通过。另修正 B4 的会话工具装配，使非 B4 用例保持原调用参数约定，B5 回归通过。

## 真实运行入口

环境文件就绪后，从仓库根目录执行，默认加载向上查找到的 `.env`：

```bash
uv run python -m evals --suite b4 --budget 0.10 --budget-currency CNY --timeout 30
# USD 模型须使用对应端点与模型配置，并将预算币种改为 USD。
uv run python -m evals --suite b4 --case b4-stale-history --budget 0.10 --budget-currency CNY
uv run python -m evals.compare --strict <报告A.json> <报告B.json>
```

预算沿用当前端点价目契约；未知端点或币种不符拒绝原币种计费。真实结果须另存原始报告，
七项全部通过且无业务写入尝试才达到模型门槛。不得用本次 mock 结果替代真实调用。
