## 工程交付

- 明确的本轮草稿 ID 历史查询，由应用先调用正式 MCP 取得该目标的实际结果，
  再交给模型作答；当前任务列表不能替代查询依据。前置调用标记 `application-read-*`，
  不将应用选择归功于模型。引号备注和旧用户消息不能触发该路由。
- 数量修改公开 MCP schema 必填 `expected_sku`；桥接参数采用严格类型，本轮读到的
  草稿 / 版本 / 行号 / SKU 必须一致。草稿响应新增后端计算的 `item_count` 和 `item_number`。
- 提交因版本、报价、库存等复核失败，或审批被拒绝 / 过期 / 取消后，程序输出固定业务说明并
  结束本轮，不再让模型自行修改、刷新或重提；同批未执行的写调用取消。结果不确定时仍走原对账路径。
- 新增三条完整任务、28 个受控阶段，逐阶段核对全表、目标约束、来源延续、实际批准版本、
  订单 / 库存以及最终可见 JSON。失败即停止后续依赖阶段，禁止用最终正确掩盖中间错误写入。

`expected_sku` 是 MCP 调用契约变更，其他 MCP 调用方需要补传；可信 Python 集成保留原可选参数。
前置历史路由只承诺说明文档列出的明确查询格式，不是任意自然语言意图理解。
行数由工具提供并进入指引，不承诺彻底消除模型的所有事实表述错误。
