## 开发依据与交付

岗位样本、日期、来源可读性和求职定位见[岗位对齐](../../docs/job-readiness-2026-10-19.md)。重点是 Agent 应用 / 后端工程：工具与编排、业务状态、可检索证据、错误处理、评测和成本。学历、年限、云上生产经验不通过项目功能数量替代。

- `evals.gate`：对原始 JSON 报告执行覆盖、执行完整性、逐轮引用与汇总一致性、结果一致性、禁止工具、计量与可选性能 / 成本检查；单独生成 JSON / Markdown。
- `configs/evals/`：baseline、B4、B4-reference、B5、B6 五份固定 case 策略。B4 / B4-reference 固定每场景轮数；默认成功率 1.0。性能和金额阈值可配置，未给默认策略虚构未测量的 SLO。
- 同模型跨版本参考检查允许源码 hash 改变，继续要求 case / scorer / seed / 重试 / 超时与业务指纹匹配，逐 case 拦截“总成功率没变但已通过场景退步”。`compare --strict` 默认仍要求同源码。
- 新报告的 `tool_attempts` 在 `ToolCallStarted` 留证，跨重试累计，并汇总到多轮父结果；中断前没有 Finished 的请求也可检出。旧报告未记录时保留 `None`，不回填虚构的空数组。
- 原币种费用按 Decimal 合计；多轮不重复计数，父金额未知时保留可恢复的子金额小计并标记不完整；父 token、时延、已知金额与子轮次交叉核对。
- 真实评测 CLI 支持 `--gate` / `--regression-baseline`，范围错误与参考报告完整性缺证据在解析供应商前退出。CI 原有付费 baseline 步骤已接线并上传派生产物，未触发远端 CI。

运行方式、配置口径与退出码见[操作契约](../../docs/eval-quality-gates.md)。
