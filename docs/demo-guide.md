# Erpilot 本地求职演示

2026-10-28 新增“商品名称下单”按钮：在新会话发送预填的完整名称与中文件数，核对青瓷茶具 A1001 两件、宣纸礼盒 B2001 三件、金额 ¥350、预算 ¥500；展开“查看原始商品要求”，刷新后来源保持。此入口使用正式 API / MCP 和临时 ERP，模型仍为离线脚本。[自然输入说明](natural-order-entry.md)。独立命令行演示现有 11 个场景。

这套演示用脚本化模型和固定关键词向量替代付费服务，执行正式的 API → LangGraph → MCP → ERP 数据库链路。适合在面试时展示工具执行、版本审批、政策证据、只读建议与历史恢复。真实模型和真实嵌入表现请查看独立评测报告。

## 启动与关闭

需要 Python 3.12+、uv、Node.js 22+ 和 npm。首次安装依赖需要联网，演示运行不需要模型密钥、嵌入服务或 PostgreSQL；不会加载项目 `.env`。

在仓库根目录执行：

```sh
python scripts/quickstart.py
```

该入口按锁文件安装、构建前端并启动。若只检查环境，运行 `python scripts/quickstart.py doctor`；
已安装依赖时可运行 `python scripts/quickstart.py demo --skip-install`。端口冲突可加 `--port 8877`。

等价的手工步骤（用于排查某一步）：

```sh
uv sync --all-packages --frozen
npm --prefix apps/web ci
npm --prefix apps/web run build
uv run python scripts/demo.py --serve --port 8765
```

打开 <http://127.0.0.1:8765>，页面应显示「离线脚本化演示」及「临时数据」。用页面顶部指令按钮填入消息，再按 Enter 发送。仅支持固定指令；其他输入会提示使用演示指令，不发起业务操作。

在启动终端按 Ctrl+C 关闭。每次服务启动使用独立临时 ERP 库、会话库和内存 checkpoint，关闭后数据清空；刷新页面会保留当前进程内的会话。演示 trace 留在 `traces/browser-demo/<本次标识>/`。这是单机、单进程演示，不用于演示 PostgreSQL 崩溃恢复。

重启后浏览器若提示旧会话恢复失败，点击「开始新会话」即可。右侧订单草稿表单点击「请求提交版本…并审批」后，先核对弹窗中的客户、备注和完整报价，再点击「确认此版本并申请审批」；随后独立审批卡上的「批准」才会执行建单。

若本机已同步依赖但没有 uv，可把 `uv run python` 替换为虚拟环境解释器：Windows 为 `.venv\Scripts\python.exe`，Linux/macOS 为 `.venv/bin/python`。

第 5 步之后刷新或从历史会话返回，可以查看已有工具结果和证据快照，不重新检索或执行业务。

页面的草稿编辑表单也连接临时 ERP，可手动修改。脚本消息中的第二行固定改为 50 件，提交依赖当前会话唯一的未提交草稿；多份草稿会提示先明确目标。为了按上表复现，请在新会话中按顺序操作，不额外创建草稿。

预算演示可另开新会话：通过表单创建 A1001 × 10、预算 ¥500 的草稿，报价 ¥980，显示超额 ¥480 且不能提交；刷新页面后预算仍在。将预算明确改为 ¥1000，保存版本 2，重新核对后申请审批并批准，订单金额仍为 ¥980。此过程使用表单和专用确认入口，不请求模型。

兼容原演示指令：「报价」查询 A1001 10 件；「批准」或「拒绝」都先预览入库 5 件，再由页面实际审批按钮决定执行；「恢复」尝试超量出库，业务预览拒绝后查询库存，不进入审批。这里的恢复是业务错误恢复。

## 离线验收与证据

```sh
# 统一工程验收，包含锁定安装、测试、构建、十一场景和浏览器；日志自动保存
python scripts/quickstart.py verify --browser
# 十一个场景，各用独立临时 ERP 库；命令行按固定决策自动批准或拒绝
uv run python scripts/demo.py
# 只重跑指定场景，不调用真实模型
uv run python scripts/demo.py --scenario order --scenario replenishment
# 浏览器连接真实本地 API，无接口结果替身；先完成前端构建
cd apps/web
npx playwright install chromium
npm run test:demo
```

命令行输出 `verified` 与逐项 `checks`，任何失败使进程退出码为 1。`traces/demo/<本次标识>/summary.json` 记录场景、实际工具、审批次数、每轮库存、变化的业务表和逐轮 trace 路径；同目录下有可阅读的 Markdown 回放。只读场景比较 ERP 全表前后快照，草稿场景验证批准版本、金额、库存及订单数。

演示显式关闭远程 trace sink；模型 HTTP 请求由内存 MockTransport 响应，政策向量在内存生成，不读取真实索引。测试阻断默认 HTTP 传输、默认政策 resolver、环境模型配置和远程 sink 装配，防止意外回退。页面不会展示虚构 token 消耗、费用或真实模型成功率。

浏览器验收使用独立端口 8766，覆盖 320/1440px 的真实政策与补货卡、历史回放零新 POST、草稿刷新恢复、拒绝后重新批准。默认 Python 路径为仓库虚拟环境，其他位置可设 `ERPILOT_DEMO_PYTHON`；已有 Chromium 可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定路径。
