判断：核心能力已超出 MVP。当前收益最高的工作是稳定可复现入口、验证工程闭环、整理展示证据。保留 Python / LangGraph / FastMCP / FastAPI / React；不增加框架和新业务模块。

## 阶段一：可复现运行与验收

交付：纯标准库的一键入口，负责环境诊断、按锁文件安装、前端构建、无密钥演示和离线工程验收；失败返回非零退出码并保存逐步日志。默认演示沿用正式 API → LangGraph → MCP → 临时 SQLite，使用明确标注的脚本模型及演示向量。

验收：静态检查、全仓 Python、前端测试与构建、十一场景离线断言；浏览器验证和 PostgreSQL 集成单列。缺少 PostgreSQL 时明确跳过，不把跳过写成全通过。用临时目录绕开本机旧 pytest 目录权限，不修改用户数据或目录权限。

## 阶段二：产品与求职材料收口

交付：README 以场景、演示、架构、技术取舍、可核对证据为主；补充实际架构与边界，更新状态页、演示指南和面试材料。实验功能与默认能力清楚标示；历史报告保持原判定。

验收：新人按 README 可直接启动；主要本地链接有效；文档与代码的存储、执行权和依赖边界一致；求职描述能回答“模型能决定什么、应用如何约束写入、失败如何恢复、如何评价结果”。

## 阶段三：展示验证与交付证据

交付：真实构建产物上的桌面 / 手机浏览器走查；完整拒绝、重提、批准及刷新恢复路径；记录最新验收、成熟度和剩余限制，生成可验证源码快照。

验收：无浏览器异常、关键业务断言通过、界面无横向溢出；源码包经哈希校验且不含密钥、个人配置或业务库。遇到实际缺陷就修复并追加针对性验证，不为凑测试数增加重复测试。

## 范围与完成口径

- 交付目标为可信单用户、单 API 进程的本地求职作品；公网多用户系统需要身份认证、审批归属和多 worker 执行权设计。
- 不改 `.env`、现有业务库、历史 scorer、人工待审核标签与实验功能默认值。
- 保留已冻结批次与缺 usage 的账本。当前可先完成零付费工程验收，不自动重开历史模型批次或用户已跳过的供应商验收。
- 四项成熟度按可验证结果自评；“本地作品可展示”和“生产级系统”分别描述，不用测试数量代替能力边界。
