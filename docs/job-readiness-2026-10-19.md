## 后续开发顺序与完成标准

B4-reference 七轮与 B6 七场景均已使用独立预算完成最终同源码两模型验收，原失败与费用证据完整保留。B4 旧账单本地复核一致；用户跳过供应商核销，原金额未知和冻结预算继续保留。

1. **收口政策结束与问题选择**：本轮检索绑定、结构化选证 / 缺口和程序原文渲染已完成；新独立完整验收两模型各 11/13，未见此前的无观测订单声明，但严格门槛未达成。下一步让可信程序直接结束不可用 / 冲突 / 失效 / 无命中状态，并区分真实问题与背景条件，再单列验收。此前未知用量批次保持冻结，最新批次没有新增未知费用。默认 0.57 阈值与 36 条检索 test 保留，大语料 / 重排继续依据独立证据决定。
2. **上下文工程已有独立实验**：[本批验收](../reports/acceptance/2026-10-19-context-and-portfolio.md)固定长历史 / 大响应，真实历史快照答题候选 GLM 8/10、DeepSeek 9/10，原策略各 2/10，输入 token 分别减少 62.71% / 62.00%；不是 24 / 48 轮模型连续业务任务完成率。GLM 行号错误、未持久化独立约束丢失和预算溢出保留；候选维持可选，后续再单列真实业务任务回归。已补[作品入口](portfolio-overview.md)、字幕录屏与[三个讲解案例](interview-cases.md)。
3. **再考虑服务化范围**：若目标岗位要求线上服务，先设计认证、会话归属与并发执行权，再单列部署验收；当前可信单用户范围不冒充多租户服务。

现阶段简历可以客观描述“实现了什么、如何验证、失败如何定位”，并附具体报告链接；B6 可说明“固定七场景最终同源码两模型各通过一次”，同时保留失败迭代。不要写“覆盖所有 Agent 岗位”“生产可用”“长期 100% 成功”或未经测量的效率提升。基础算法、系统设计、本人对代码的理解与讲解能力仍需独立准备。
