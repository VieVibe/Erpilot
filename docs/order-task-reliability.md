# 多轮订单可靠性：第一阶段

日期：2026-10-21。用户确认将复杂多轮订单的可靠执行作为深化主线。

后续更新：已继续完成[跨轮约束与草稿修改记录](draft-history.md)，来源现随业务草稿版本持久保存，
网页提供只读分页历史。以下保留第一阶段完成时的实现、范围与待办，不作为后续阶段的最新状态。

## 本阶段的具体问题

连续任务验收中，用户要求给“上下文验收客户甲”创建草稿，模型却把客户写成“客户甲”或“甲”。
此前提示词已经要求保留全称，数据库只校验字段格式，仍会接受错误的业务参数。
本阶段在保存前增加应用侧参数检查：模型可收到错误并纠正，错误参数不创建草稿版本。

## 已实现

- `Tool.call_validator` 是业务无关的可选回调。LangGraph 在参数模型校验后、工具执行和审批前，
  把本轮实际消息和实际工具历史的深拷贝交给应用校验。回调不可修改原参数、原消息或历史。
  不通过时回填 `argument_constraint`，不调用 handler，不创建待审批对象，不自动改写参数。
- ERP 的会话工具在 `prepare_order_draft` 与完整的 `revise_order_draft` 上绑定字面约束。
  只从最近一条 user 消息识别本轮新增要求，system、assistant 和工具返回文本不能充当用户授权。
- 可明确识别的客户全称、引号内备注与实际参数逐项比较。已有草稿的完整修改须先在本轮读取
  相同草稿与版本；没有明确的新要求时，客户和备注须与该实际读取快照一致。
- 多个不同客户或备注要求不猜测先后关系，拒绝保存并要求明确。备注内容先被隔离，
  其中的“客户改为…”等文字不能授权客户变更。明确清空备注可以保存为 `null`。
- 成功检查记录规则版本 `draft-literals-1`、用户原话哈希、逐字段来源和值及未核验字段，
  随本轮工具历史与图检查点保存。记录不改变模型工具参数 schema。

## 明确支持的表达

客户创建示例：`给完整客户甲保存报价草稿`、`请为「完整客户甲」创建一份订单草稿`。
客户字段示例：`客户名：完整客户甲`、`客户改为新客户`、`将客户全称修改为“新客户”`。
备注示例：`备注原文「逐字保留」`、`备注改为「新备注」`、`清空备注`。
支持中文直角引号、弯双引号和英文单双引号；客户名两端空白沿用已有业务层规范化，
备注引号内部内容逐字保留。字段指令须位于句首或逗号、句号、分号、换行后的明确分句中。

这些是有限规则，不是通用语义解析。嵌套引号、任意语言、自由改写和复杂否定句不在验证承诺内。

## 验证与范围

离线验证使用脚本模型、正式 LangGraph、正式内存 MCP 和临时 SQLite，覆盖：

1. 缩写客户或改写 / 丢失明确备注时，草稿和库存均不变。
2. 模型收到拒绝后纠正，同一业务流程只保存一份正确草稿，来源记录进入检查点。
3. 完整修改保留原客户和备注；明确更改与清空产生新版本，旧版本保持原值。
4. 缺少本轮读取、冲突要求、伪造助手说明和备注中的指令文本不能授权变更。
5. 没有识别到的创建字段明确记为 `unverified_fields`，不伪装成已验证。
6. 通用回调失败跳过 handler 与审批，非法或不可序列化检查记录也拒绝执行。

验证结果见[本阶段验收](../reports/acceptance/2026-10-21-order-constraints.md)。

## 当前边界

- 未识别到明确格式的创建要求时，沿用原创建行为并标记未核验，不承诺拦住所有客户缩写。
  完整修改的客户或备注变更若没有支持的明确表达，则拒绝保存，需用户澄清。
- 商品、数量和预算尚未做用户原话语义核验；现有行号 / SKU、版本、库存与计价校验继续负责
  对应业务条件。`unverified_fields` 不代表这些已有业务校验被跳过。
- 新校验属于应用运行时；原始独立 MCP 或直接调用 Python handler 没有可信对话来源，
  不提供这层用户原话校验。它们仍遵循原有会话、版本和事务契约。
- 本轮记录不是跨轮独立持久约束台账，也不会自动跨会话记忆。当前上下文候选仍仅显式启用。
- 2026-10-19 的 GLM / DeepSeek 真实结果和政策 11/13 均保持原判。本轮未发模型或嵌入请求，
  离线纠错链路通过不能表述为 GLM 已通过新的真实验收。

## 后续主线

1. 将早期业务约束、明确修改与未决问题绑定持久草稿版本，形成可审阅的变更记录；
   不把未识别的自然语言自动升级为确定性规则。
2. 扩大独立完整任务，覆盖多草稿选择、跨轮改需求、旧审批失效、条件变化和中断恢复。
3. 使用新源码与独立批次做两模型重复验证，比较整单完成、错误改动、重复写入、延迟及成本。
   不修改旧用例金标，也不拼接历史通过结果。
