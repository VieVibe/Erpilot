# 订单预算上限与待确认事项

日期：2026-10-21。预算是可选的人民币订单约束。用户明确设置后，随不可变草稿版本保存；修改商品、数量或刷新价格会重新检查预算。

后续更新（2026-10-27）：[P0 / P1](order-reliability-p0-p1.md)将待确认事项扩展到有效期、版本、商品条件与库存；本页保留预算专项契约及原批次结果。

## 用户操作

- 对话支持明确分句：“预算上限为3000元”“总价不超过3000元”“预算改为3500元”“取消预算上限”。用户原话、请求哈希和确立要求的版本一起保存。未支持的预算表达要求澄清，不能静默忽略。
- 表单新增“预算上限（元，选填）”。留空为未设置；修改或清空已有预算后，必须保存新版本。表单填写与聊天原话分别标注来源。
- 面板、核对窗口和审批摘要显示预算、当前报价及来源。报价超预算时显示“待确认：报价超出预算”和差额，禁用提交。保存、编辑仍可进行。
- 用户明确提高预算、取消上限或调整商品后，保存新报价版本，再重新核对和审批。模型不能自行抬高预算或减少商品数量来消除冲突。

例如：预算 ¥3000，报价 ¥3000；新增商品后报价 ¥3200，产生 ¥200 超额事项，提交被拒绝；用户明确改预算为 ¥3500，保存新版本，再核对并审批，按 ¥3200 建单。旧报价、旧预算和原始来源保留。

预算必须为大于零、不超过一万亿元且最多两位小数的金额，精确相等允许提交，超出一分也受阻。预算检查使用十进制差额，作用于现有 `total_amount`；本阶段只覆盖人民币报价，未扩展多币种或额外运费 / 税费规则。

## 执行与持久化

沿用 `order_drafts.snapshot`，没有新增表或列。每次保存原子写入：

- `budget_limit`：金额或 `null`。
- `budget_constraint`：人民币币种、金额、来源和确立版本。来源为用户原话、表单、未归属调用或未设置。
- 原有 `change_record` 新增 `budget_limit` 差异；历史接口每版本附带当时的 `budget_constraint`。客户 / 备注的 `task_constraints` 契约保留。

读取时由后端计算 `budget_check`（上限、报价、超额、状态）与 `pending_issues`。本阶段待确认事项只覆盖预算超额；金额回到预算内或预算明确改变后，由新版本事实重新计算，不依赖模型宣称“已解决”。旧快照没有预算时不补造要求。

预算拦截覆盖网页专用确认接口、模型工具的审批前检查，以及领域层实际提交事务。即使绕过按钮、直接调用 MCP 或已有审批恢复，仍须满足预算和原有版本 / 报价 / 库存契约。预算变化生成新版本，旧审批不能授权新版本。

模型提交超预算草稿时，可信校验返回 `budget_exceeded`，程序终止本轮，取消同批未执行的写调用；不再询问模型自行修改。实际建单后沿用原幂等重放规则。

## HTTP 与 MCP 契约

HTTP 创建和修改草稿增加可选 `budget_limit`：

- 创建时省略或 `null` 表示未设置。
- 修改时省略表示保留；显式 `null` 表示通过表单明确取消；数值表示设置新上限。
- 布尔值、数字字符串、非正数、多于两位小数等拒绝保存。
- 专用确认接口发现超额返回 HTTP 409 / `budget_exceeded`，不创建审批或业务订单。

MCP `prepare_order_draft` 增加可选 `budget_limit`。`revise_order_draft` 可设置新 `budget_limit`；省略或 `null` 保留，明确取消使用 `clear_budget=true`。同时设置数值和取消标志会被拒绝。数量工具始终继承已有预算。

模型侧只能从本轮真实用户分句及本轮实际读取的草稿取得依据，旧消息、助手消息和引号备注中的预算文字不能授权改预算。来源证据由应用装配，不是模型可提交的工具字段。原始 MCP 能创建带未核验来源的预算，但没有可信新依据时不能更改已有预算；领域提交仍执行金额约束。可修改程序或数据库的可信调用方不在身份认证边界内。
