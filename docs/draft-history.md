日期：2026-10-21。本阶段承接[保存前参数检查](order-task-reliability.md)，把有限范围的
客户 / 备注来源保存到业务库，并提供可审阅的版本变更。后续已补[完整订单任务验收](whole-order-acceptance.md)；
[最新真实结果](../reports/acceptance/2026-10-21-whole-order-acceptance.md)中 GLM 历史 2/2，跨模型共同门槛仍未达成。

## 用户可以做什么

后续新增[预算约束](order-budget.md)：历史每个版本附带 `budget_constraint`，差异包括预算上限变更；客户 / 备注来源结构保持兼容。

2026-10-22 新增[商品变更核验](draft-item-constraints.md)：已有草稿通过应用校验后，
历史中的 `change_record.item_guard` 保存本轮要求、读取版本与实际前后商品明细。
它不改变客户 / 备注来源，也不把初始商品选择标记为已核验。

- 恢复旧任务后，查询草稿仍能取得原客户、备注及其来源，不需要恢复旧聊天文字。
- 编辑数量会保留这些来源；更改已核验的客户或备注，需要本轮明确的新要求，或通过表单明确编辑。
- 网页草稿下点击“查看修改记录”，按版本查看商品数量、顺序、报价等实际变化，展开本次用户请求。
  记录只读，支持更早版本分页；查看、刷新或切换会话不会重放旧请求。
- 旧草稿没有来源记录时显示未核验，不反推或补造原始用户要求。

## 存储与来源

沿用 `order_drafts.snapshot` JSON，每个新版本同时保存：

- `task_constraints`：`schema_version=1`、客户 / 备注的值、`verified` 和原始 `origin`。
  来源为 `user_literal`、`manual_form`、`unverified` 或兼容旧记录的 `legacy_snapshot`。
  用户字面来源含连续原话、原请求 SHA-256 和确立该要求的版本号。
- `change_record`：当前 / 前序版本、操作类型、来源、本次用户请求和后端从前后快照计算的实际差异。
  来源为 `agent`、`manual_form` 或 `unattributed`，不把缺少原话的调用描述为用户明确要求。

没有新增数据库表或列。版本、来源与差异在同一事务提交；失败时一起回滚。
数量编辑、报价刷新或同值确认保留既有已核验来源，不覆盖老版本。
新要求改变字段时只替换该字段的来源；明确的表单输入也能核验此前来源未知的字段，
不会因此追溯修改旧版本的来源状态。

`verified` 只表示该字段的值有本阶段支持的字面或表单来源，不表示整个任务语义都通过验证，
也不是登录身份、审批权限或价格 / 库存的保证。商品和数量仍不在通用用户原话语义核验范围内；预算的有限明确表达与执行约束见[预算契约](order-budget.md)。

## 来源如何进入业务层

1. LangGraph 的应用回调读取本轮实际 user 消息和实际工具历史，校验字面要求。
2. 非审批草稿工具的 `validated_handler` 收到这份独立的检查记录；MCP 工具参数不增加来源字段。
   当前桥为每次调用创建独立 MCP 实例，通过服务端装配把记录交给草稿业务层。
3. 业务层再次校验契约、请求哈希、原话片段、字段值与前序版本，再写入不可变快照。
   已保存的已核验字段不能通过没有新依据的原始 MCP 修改。
4. 手工表单的来源由 HTTP 路由固定装配，不接受请求体声明自身来源。直接 Python 集成属于可信
   应用代码；该机制不对能修改程序或数据库的调用方提供身份认证。

通用工具结构禁止同时设置审批风险和 `validated_handler`，避免来源处理路径绕过审批。
建单仍走原来的版本审批、执行时复核及幂等契约。

普通草稿响应只携带当前 `task_constraints` 和精简的 `last_change`。
完整差异和原请求按需读取，避免把大量商品的新增明细在每次草稿查询中重复返回。

## 只读查询契约

HTTP：`GET /api/sessions/{session_id}/order-drafts/{draft_id}/history`。

MCP：`get_order_draft_history(draft_id, before_revision=null, limit=5)`。

`limit` 为 1–20；`before_revision` 是排除该版本的正整数游标。结果包括版本倒序 `items`、
`latest_revision`、`has_more` 和 `next_before_revision`。会话由宿主绑定，跨会话和不存在的草稿
统一返回 `not_found`。旧记录的 `change_record=null`，来源状态保持未知。

后续应用对本轮明确 ID 的查询先做实际只读查询，再请求模型回答；应用选择的读取明确标为
`application-read-*`，不归功于模型自主选工具。范围和未支持格式见[完整任务说明](whole-order-acceptance.md)。

页面仅在用户展开时请求记录，校验返回目标、版本顺序、游标、来源类型与差异值。
切换草稿、版本或会话会取消旧读取；迟到结果不能写入新面板。原话按纯文本显示，
不能执行 HTML、脚本或历史指令。
