## 目标与边界

把查询、建议、审批、执行连接为可验证的业务流程，继续服务于「会请示的 ERP 智能体」作品集定位。优先完成报价建单闭环，再深入任务状态和政策依据；以验收结果推进，不承诺固定发布日期。

维持本机可信单用户范围、现有 LangGraph / MCP / SQLite / PostgreSQL checkpoint 架构及 `agent_core` 零业务依赖。不扩展完整 ERP、支付网关、多租户、多 agent 编排或自动采购。

## B1 的明确计价契约

1. 先合并同一 SKU 数量，再按该 SKU 的总数量命中折扣；不同 SKU 不累加。
2. 数量 10/50/200 件起分别为 98 折、95 折、9 折，低于 10 件无折扣。
3. 以十进制计算折后单价，按四舍五入（ROUND_HALF_UP）保留两位；行金额 = 已舍入单价 × 数量；订单金额 = 各行金额之和，保留两位。
4. 新订单保存下单时的折后成交单价，历史订单不重新计价；幂等重放返回原提交结果，不采用新现价。
5. B1 不承诺冻结旧报价。当前报价是参考；执行时按现价计价。B2 才引入批准版本与价格变化复核。
6. 保持现有 API 金额数值字段、数据库结构和历史订单汇总算法；报价及新单成交单价使用十进制计算，不宣称完成全库金额类型迁移。折后单价舍入为零时报价和建单均返回业务错误，避免零价单。
