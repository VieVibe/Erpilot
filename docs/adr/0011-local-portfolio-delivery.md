# ADR-0011：本地求职作品交付与统一验收

- 状态：已接受并实施
- 日期：2026-11-04
- 依据：[成熟度诊断](../plans/2026-11-04-portfolio-maturity.md)、[实际架构](../architecture.md)

后续范围更新：[ADR-0012](0012-authenticated-container-deployment.md)增加带账号的前端/API容器和持久演示。
本页保留此前本地收口的决策依据；其“仅 PostgreSQL 容器、可信单用户”范围已由新 ADR 扩展。
语义默认关闭约定已由 [ADR-0013](0013-default-semantic-proposals.md)更新，人工标签状态保留。

## 问题

已有业务和恢复深度足以支撑求职展示，但新人需要组合安装、构建、启动和测试命令。
README 的历史迭代记录掩盖推荐入口；早期栈规划还包含未使用的网关、向量库和评测框架。
新增框架或业务模块不能解决首次复现与证据可读性问题。

## 决策

1. 保留现有运行时与分包。新增纯 Python 标准库 `scripts/quickstart.py`，无需先导入业务包，
   提供只读 `doctor`、默认 `demo` 和 `verify`。缺依赖、端口占用或某步失败均明确退出。
2. 默认依次执行 `uv sync --all-packages --frozen`、`npm ci`、构建及正式离线演示。
   不自动安装全局工具、读写 `.env` 或启用付费模型。依赖安装本身需要网络。
3. `verify` 保存逐步日志与 JUnit，默认排除真实模型评测；浏览器与 PostgreSQL 作为显式范围，
   跳过不能写成完整通过。CI 同样按现有锁文件安装。
4. 交付定位为可信单用户、单 API 进程的本地作品。Docker Compose 继续仅提供正式 API 所需的
   PostgreSQL；不为公开部署补一层无法证明访问控制的包装。
5. README 展示当前场景、入口、架构、技术取舍和独立证据。历史报告保留原判定，
   实验语义功能默认 off，人工待审标签不自动升级。

## 取舍

- **采用标准库入口而非 Make / PowerShell / Bash 组合**：已有 Python 前置条件，跨平台参数和失败语义统一。
- **先提供本地闭环而非增加全栈容器镜像**：面试展示无需 Docker 守护进程或付费配置；正式 API 仍可验证 PostgreSQL 恢复。
- **安装与运行区分**：首次按锁安装，重复展示可 `--skip-install`，每次重新构建避免展示旧前端。
- **不自动升级依赖**：本次问题是交付一致性；升级需独立确认行为变化和兼容性，不混入文档收口。

## 后果

仓库和源码快照都能使用同一启动路径。验收日志位于忽略的 `artifacts/verification/`，
可按需复制为带日期的报告。首次依赖下载、浏览器平台库和真实 API 的密钥 / PostgreSQL
仍是明确的环境条件，不由脚本隐式代办系统安装。
