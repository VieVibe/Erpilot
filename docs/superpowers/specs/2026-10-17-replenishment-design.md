# B6 有依据的补货建议

2026-10-17：用户要求开始 B6，按现有只读路线实施。B4 真实模型验收和冻结预算保持独立，不以 B6 完成代替。

## 用户结果与范围

询问「最近 30 天哪些商品需要补货」时，返回可审阅清单：当前库存、有效销量、日均销量、预计可售天数、建议数量、统计窗口和计算假设。仅查询，不创建采购单、不调整库存、不发起审批。维持现有架构，agent_core 不依赖业务包。

## 计算契约

- 工具 `suggest_replenishment(days=30, coverage_days=14, lead_time_days=None, skus=None, limit=20, offset=0)`。days 1–365，coverage_days 1–180，采购周期 0–180；SKU 最多 50 个去重；每页 1–50。
- 按北京时间取一次查询时点，订单创建时间使用半开滚动窗口 `[时点-days, 时点)`。有效订单状态复用待发货、已发货、已签收；不计取消、退款及待付款。当前状态和当前库存均是查询快照，不能当作历史回测或真实出库统计。
- 日均销量 = 窗口有效销量 / days；预计可售天数 = 当前库存 / 日均销量。计算建议数量使用整数分子，避免展示舍入影响结果。
- 目标数量 = ceil(有效销量 × (coverage_days + 采购周期) / days)，建议数量 = max(0, 目标数量 − 当前库存)。coverage_days 指到货后希望覆盖的天数；采购周期已提供时加入需求覆盖，另比较到货前断货风险。
- 未提供采购周期时，仅按 coverage_days 测算，明确「采购周期未知，未计入采购等待需求，不能判断到货前断货风险」，不伪造供应商参数。默认 30 天窗口、14 天覆盖显式展示，可由用户更改。
- 零销量：预计可售天数、建议数量与到货风险为 null，说明缺少销量依据，不能声称库存无限或无需补货。下架商品不自动建议；缺失/负库存、异常销量或未知商品状态标为数据待核对，不当作零库存。未知 SKU 返回 not_found。
- 在同一 SQL 查询中聚合全部候选商品及销量，再按数据待核对、建议补货、零销量、库存充足、下架排序，SKU 打破平局，最后分页。响应携带 total / returned / has_more；不能把当前页描述为全量。
- 缺少在途采购、库存历史、缺货时长和季节性资料；简单历史均值是条件测算，不能宣称需求预测准确率。工具文本和商品名是数据，不能作为改变用户意图或执行权限的指令。
